# 포크/업스트림/Cloudflare Workers 운영 계획

## 추천 운영 방식

- `upstream`은 `https://github.com/choyiny/saasmail`로 둔다.
- `main`은 `upstream/main` 추적용 브랜치로 유지한다.
- 업스트림 PR은 항상 `main`에서 분기한 `feature/*` 브랜치로 만들고, 대상은 `choyiny/saasmail`의 `main`으로 맞춘다.
- 개인 Cloudflare Workers 배포는 `deploy/prod` 같은 별도 배포 브랜치에 연결한다.

## 근거

- `CONTRIBUTING.md`는 `main`에서 브랜치를 따고 PR을 `main`으로 보내는 흐름을 전제로 한다.
- `README.md`는 `upstream/main` 기준으로 동기화하는 포크 워크플로우를 문서화한다.
- `.gitignore`와 `README.md`는 `wrangler.jsonc`를 각 deployer가 로컬에서만 유지하는 gitignored 설정으로 정의한다.
- 현재 `wrangler.jsonc`에는 실제 Cloudflare 계정/도메인/D1/R2 정보가 들어 있어 업스트림 PR에 포함되면 안 된다.
- 현재 `pnpm-lock.yaml`은 문서 전반의 `yarn` 표준과 충돌하므로, maintainer 합의 없는 업스트림 PR에는 포함하지 않는 쪽이 안전하다.

## 실행 단계에서 정리할 항목

- 현재 git remote 상태를 확인하고 `origin`은 개인 포크, `upstream`은 `https://github.com/choyiny/saasmail`로 분리한다.
- `main`을 업스트림 추적용으로 정리하고 개인 배포는 `deploy/prod` 브랜치로 분리한다.
- `wrangler.jsonc`를 인덱스/스테이징에서 제외하고 `wrangler.jsonc.example`만 공유 설정의 기준으로 사용한다.
- `pnpm-lock.yaml`를 스테이징에서 제외하고, 패키지 매니저 정책은 별도 결정으로 분리한다.
- Cloudflare Workers는 배포 브랜치만 감시하도록 연결하고, 업스트림 PR 브랜치는 배포와 분리한다.

## 검증

- `git status --short`와 `git diff --cached --name-only`로 PR 후보 파일이 `feature/*` 브랜치에서 의도한 파일만 포함하는지 확인한다.
- `git diff <upstream-branch>...HEAD`로 업스트림 PR에 개인 배포 설정 파일이 섞이지 않았는지 확인한다.
- 배포 브랜치에서만 `wrangler.jsonc` 기반 배포가 이뤄지도록 Cloudflare 브랜치 연결 설정을 점검한다.
